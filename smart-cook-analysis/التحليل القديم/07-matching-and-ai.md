# 07 — خوارزمية المطابقة والذكاء الاصطناعي

> قلب التطبيق. الهدف: اقتراحات **صحيحة، سريعة، مفهومة، وممتعة**.

## 1. مسار المعالجة

```
مدخلات المستخدم (نص/صوت/صورة/باركود)
   ↓ استخراج الكيانات (NER) + التطبيع + المرادفات
معرّفات مكونات (ingredient IDs) مؤكدة من المستخدم
   ↓
مجموعة المخزون = المكونات + الأساسيات − المستبعدات
   ↓
(1) ترشيح صارم: حساسية/حمية/معدات/وقت
(2) حساب درجة التطابق لكل وصفة
(3) إعادة ترتيب شخصي + أولوية الفساد + التنوع
   ↓
نتائج مقسمة: جاهز الآن | ينقصك 1–2 | ألهمني (AI)
```

## 2. نموذج الوصفة للمطابقة

كل وصفة تحوي مكونات مصنّفة بأهمية:

| النوع | المعنى | أثر الغياب |
|-------|--------|-------------|
| **أساسي (core)** | يعرّف الطبق (الدجاج في الكبسة) | الوصفة غير قابلة للطهي |
| **مهم (important)** | يؤثر كثيرًا (بصل، طماطم) | تقل الدرجة كثيرًا |
| **اختياري (optional)** | تحسين (كزبرة للتزيين) | لا أثر على «قابلية الطهي» |
| **أساسية مفترضة (staple)** | ملح، ماء، زيت | تُفترض موجودة |

## 3. معادلة الدرجة (نموذج أولي قابل للضبط)

لكل وصفة `r` ومخزون `P`:

```
coverage_core      = |core(r) ∩ P*| / |core(r)|            (P* = P + بدائل مقبولة)
coverage_important = |important(r) ∩ P*| / |important(r)|
missing_penalty    = 0.15 × (عدد الناقص من core) + 0.05 × (عدد الناقص من important)

score = 0.55·coverage_core + 0.30·coverage_important
        + 0.08·expiring_bonus + 0.05·personal_affinity + 0.02·freshness_novelty
        − missing_penalty
```

**قواعد قاطعة (Hard rules):**
- أي مكوّن مستبعد/مسبب حساسية في الوصفة ⇒ تُحذف الوصفة من النتائج دون استثناء.
- `coverage_core < 1` لا تُعرض في «جاهز الآن».
- «ينقصك 1» = ناقص مكوّن واحد فقط من (core+important)، ولا ناقص من core إلا عندما يوجد بديل مقبول.

**الأوزان أعلاه تقدير أولي**؛ تُضبط بالتجارب (A/B) وبيانات النقرات والطهي الفعلي.

## 4. البدائل الذكية

- جدول بدائل مُنسَّق بخبراء: (مكوّن ← بديل، نسبة، أثر على الطعم/القوام، الاستخدامات المناسبة).
- **قاعدة السياق:** البديل يصلح لبعض الأطباق دون أخرى (الزبادي بدل الكريمة في الصلصات الباردة لا الساخنة).
- مستويات: «بديل مثالي» ✓، «بديل مقبول» ~، «لا ينصح».
- يعرض التطبيق: «ينقصك الكريمة — جرّب الحليب + زبدة (قوام أخف)».
- إمكانية طلب بديل من الذكاء الاصطناعي لحالات غير موجودة في الجدول، مع تخزين الإجابات الجيدة بعد المراجعة.

## 5. الفهرسة والأداء (على الجهاز)

- كل وصفة تُمثَّل **بقناع بتّي (bitmask)** أو مجموعة مرتّبة لمعرّفات المكونات.
- فهرس معكوس: `ingredient_id → [recipe_ids]` للوصول السريع.
- خطوات: اجمع المرشحين من الفهرس المعكوس (الوصفات التي تشارك مكونًا مع المخزون) ثم احسب الدرجة.
- تنفيذ الحساب في **Isolate** منفصل لتجنب تعطيل واجهة المستخدم.
- الهدف: < 300ms لعشرة آلاف وصفة. للأعداد الأكبر، دفع جزء الترشيح للخادم (Postgres + فهارس GIN على مصفوفات المكونات).

## 6. إدخال المكونات بالذكاء الاصطناعي

### 6.1 الصوت
1. التعرف على الكلام (STT): على الجهاز (للخصوصية والسرعة) أو سحابيًا عند الحاجة لدقة اللهجات.
2. **استخراج المكونات:** مطابقة نصية مع قاموس المرادفات (Aho-Corasick/ n-gram) + نموذج لغوي صغير لحالات الجمل المعقدة («عندي نص كيلو لحمة وشوية بصل»).
3. شاشة تأكيد.

### 6.2 الصورة (الثلاجة/الرف)
- نموذج رؤية متعدد الوسائط (سحابي) يُرجع JSON: مكونات + ثقة + كمية تقريبية.
- **الإستراتيجية الهجينة:** نموذج خفيف على الجهاز (مثل TFLite/ML Kit) للكشف السريع عن الأطعمة الشائعة + نموذج سحابي للتفاصيل عند الحاجة.
- **مخاوف:** التعرف على التوابل المعبأة والأوعية المغلقة ضعيف؛ لذلك **تأكيد المستخدم إلزامي**، ونعرض «غير متأكد» بوضوح.
- **الخصوصية:** معالجة مؤقتة، عدم تخزين الصور، إخفاء الوجوه/المحيط إن أمكن، إعلام بالموافقة.

### 6.3 الباركود/الإيصال
- باركود → قاعدة منتجات مفتوحة أو تجارية → تحويل منتج إلى مكوّن.
- إيصال → OCR → مطابقة أسماء المنتجات (تحدي كبير بالعربية والتهجئة) — مؤجل لـ V2.

## 7. الذكاء الاصطناعي التوليدي المسؤول («ألهمني»)

### 7.1 متى؟
- عند عدم وجود تطابق جيد، أو بطلب المستخدم (مثلاً «اجمع لي طبقًا مبتكرًا من هذه المكونات»).

### 7.2 البنية
```
طلب المستخدم + المخزون + القيود
   ↓ (الخادم فقط — لا مفاتيح في التطبيق)
بناء الأمر (Prompt) + سياق: وصفات قريبة من قاعدتنا (RAG)
   ↓
نموذج لغوي → مخرجات JSON مهيكلة (مكونات بمعرّفات، خطوات، أوقات)
   ↓
مدقق آلي: 
   - المكونات ضمن المخزون/المقبول؟
   - لا مسببات حساسية محظورة؟
   - حرارة/وقت آمنان للحوم/الدواجن؟
   - الكميات منطقية؟
   ↓
وسم «مقترح بالذكاء الاصطناعي — غير مُجرَّب»
```

### 7.3 ضوابط الأمان والجودة
- **مخرجات مهيكلة** (Schema) بدل نص حر لتسهيل التحقق.
- **RAG:** إرفاق وصفات موثّقة قريبة كمرجع يحدّ من الهلوسة.
- **قواعد سلامة صلبة** في الكود (لا تُترك للنموذج): حد أدنى لحرارة الدواجن، تحذيرات الأطعمة النيئة، منع مواد غير صالحة للأكل.
- **تقييم دوري:** مجموعة اختبار من 300 طلب + مراجعين بشريين لقياس: السلامة، الجدوى، الطعم المتوقع، الالتزام بالقيود.
- **حلقة تغذية راجعة:** تقييمات المستخدمين؛ الأفضل يدخل مراجعة المحررين فيتحول إلى «موثّق».
- **حدود الاستخدام:** عدد محدد مجانًا يوميًا + تخزين مؤقت للطلبات المتشابهة لخفض التكلفة.

### 7.4 اختيار النموذج
- نموذج صغير سريع للمهام البسيطة (استخراج مكونات، بدائل)، ونموذج أكبر للتوليد الكامل. تُقيَّم الخيارات بالتجربة على اللهجات العربية والتكلفة وقت التنفيذ (يمكن استخدام Claude API أو غيره).
- **لا تضع مفتاح API في التطبيق أبدًا**؛ اجعله خلف خادمك مع مصادقة وحدود معدل.

## 8. التخصيص (Personalization)

| الإشارة | الاستخدام |
|---------|-----------|
| المفضلة، التقييمات | رفع درجة وصفات/مطابخ مشابهة |
| الطهي الفعلي | إشارة أقوى من النقر |
| الإخفاء/«لا أحبه» | خفض نهائي |
| الوقت والموسم | مناسب للوقت (فطور/عشاء) والمناسبة |
| حجم الأسرة | تقديم وصفات بأحجام مناسبة |

- المرحلة الأولى: **قواعد + ميزات بسيطة** (Content-based).
- لاحقًا: تضمينات (embeddings) للوصفات + تصفية تعاونية خفيفة.
- **التنوع:** تجنب تكرار نفس الطبق/المطبخ لأيام متتالية.

## 9. قياس جودة المطابقة

| المقياس | الهدف |
|---------|-------|
| دقة الوصفات «جاهز الآن» (لا ناقص حقيقي) | ≥ 99% |
| نسبة بدء الطهي بعد عرض الاقتراحات | ≥ 35% |
| معدل «لا نتائج» | ≤ 2% بعد 3 مكونات أو أكثر |
| متوسط عدد النقرات حتى الاختيار | ≤ 3 |
| تقييم رضا الاقتراحات (👍/👎) | ≥ 80% 👍 |

## 10. حالات حدّية (Edge Cases)

- مستخدم أضاف مكونًا واحدًا فقط: نعرض «ابدأ بإضافة المزيد» + وصفات عالية الشيوع بالمكوّن.
- مكونات متضاربة (بعضها نباتي وبعضها لحوم) مع حمية نباتية: التصفية تغلب.
- أسماء مبهمة («جبنة»): نسأل «أي نوع؟» أو نعتمد مجموعة «جبنة عامة».
- أحجام/كميات غير كافية (بيضتان فقط لوصفة تحتاج 6): نعرض تنبيه «الكمية قد لا تكفي» عندما تكون الكميات مُدخَلة.
- حساسية جزئية (يتجنب المكسرات الكاملة لا الزبدة): قواعد قابلة للضبط.
