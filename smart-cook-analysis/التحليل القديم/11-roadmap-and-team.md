# 11 — خارطة الطريق والفريق والتكلفة

> التقديرات تخطيطية وتعتمد على حجم الفريق وخبرته؛ عدّلها بعد مرحلة الاكتشاف.

## 1. المراحل

```
المرحلة 0: الاكتشاف والتحقق (3–4 أسابيع)
المرحلة 1: التأسيس (4 أسابيع)
المرحلة 2: MVP (8–10 أسابيع)
المرحلة 3: Beta مغلق (4 أسابيع)
المرحلة 4: الإطلاق العام (2–4 أسابيع)
المرحلة 5: V1 (3 أشهر بعد الإطلاق)
المرحلة 6: V2 والتوسع (6–12 شهرًا)
```

### المرحلة 0 — الاكتشاف (3–4 أسابيع)
- مقابلات مع 20–30 مستخدمًا من الشرائح الأربع.
- اختبار «سحر ويزارد أوز» (Wizard of Oz): مستخدمون يرسلون صور الثلاجة، وفريق يقترح أطباقًا يدويًا؛ لقياس الرغبة الفعلية.
- تحديد أسواق الإطلاق، واختيار الاسم، وتثبيت نموذج المحتوى.
- نماذج Figma تفاعلية واختبارها.
- **مخرجات:** تقرير تحقق، وثيقة المنتج (PRD)، تصميم أولي، قائمة 100 وصفة مبدئية.

### المرحلة 1 — التأسيس (4 أسابيع، بالتوازي مع الإنتاج التحريري)
- مستودع الكود، CI/CD، Flavors، الهيكل المعماري.
- نظام التصميم (Tokens + مكونات أساسية + RTL).
- قاعدة البيانات والباك اند الأساسي وCMS.
- بدء إنتاج الوصفات وبناء قاموس المكونات.

### المرحلة 2 — MVP (8–10 أسابيع)
| الأسبوع | التركيز |
|:-------:|---------|
| 1–2 | المخزون المحلي + البحث بالمكونات + الاستكمال التلقائي |
| 3–4 | خوارزمية المطابقة + شاشة الاقتراحات + الفلاتر |
| 5–6 | صفحة الوصفة + وضع الطهي + المؤقتات |
| 7 | قائمة التسوق + المفضلة + الإعدادات (حساسية/حمية) |
| 8 | الحساب + المزامنة الأساسية + التحليلات |
| 9–10 | صقل الواجهة، الأداء، الاختبارات، الوصولية |

### المرحلة 3 — Beta (4 أسابيع)
- 300–1000 مستخدم؛ جمع أخطاء وملاحظات.
- ضبط أوزان المطابقة بالبيانات الفعلية.
- اختبارات أجهزة اقتصادية.
- إعداد صفحات المتاجر وسياسة الخصوصية.

### المرحلة 4 — الإطلاق
- إطلاق تدريجي (Staged rollout) على Android، وإطلاق iOS.
- حملة المؤثرين، ASO، صحافة تقنية وغذائية.
- مراقبة يومية للأعطال والمؤشرات.

### المرحلة 5 — V1 (بعد الإطلاق بـ 3 أشهر)
- الصوت المتقدم والتحكم الصوتي في الطهي.
- تصوير الثلاجة.
- تنبيهات الفساد وتواريخ الصلاحية.
- «ألهمني» بالذكاء الاصطناعي.
- مخطط الوجبات وقوائم التسوق الأسبوعية.
- الاشتراك Pro.
- 1,500 وصفة.

### المرحلة 6 — V2
- الباركود والإيصالات، مشاركة الأسرة، وصفات المستخدمين، ويب للوصفات (SEO)، لغات جديدة، تكامل البقالة، تخصيص تعلّمي، تطبيق ساعة/جهاز لوحي.

## 2. الفريق المقترح

### الفريق الأساسي لـ MVP
| الدور | العدد | ملاحظة |
|-------|:-----:|--------|
| قائد المنتج / مدير المشروع | 1 | قد يكون المؤسس |
| مهندس Flutter أول | 1–2 | معمارية + أداء |
| مهندس باك اند/بيانات | 1 | Supabase/Postgres + CMS + AI endpoints |
| مصمم UX/UI (Senior) | 1 | نظام تصميم + RTL + حركة |
| رئيس/محرر محتوى طعام | 1 | قيادة الوصفات |
| طهاة/كتّاب وصفات | 2–3 (بدوام جزئي/تعاقد) | تجريب وكتابة |
| مصوّر طعام (تعاقد) | حسب الحاجة | صور احترافية |
| مهندس تعلم آلة (جزئي/استشاري) | 0.5 | الصوت/الصورة/RAG |
| QA | 1 (أو تعاقد) | أجهزة متعددة وRTL |

يمكن أن يعمل المؤسس مع فريق أصغر (مطوّر Flutter + مصمم + محرر محتوى) في نطاق مخفض، لكن **جودة المحتوى والتصميم** هما نقطتا التمايز؛ لا تُقتصد فيهما.

## 3. تقدير التكلفة (نطاقات تقريبية جدًا)

> تتفاوت كثيرًا حسب الدولة ونوع التعاقد (فريق داخلي/وكالة/مستقلون). استخدمها فقط كنقطة بداية للنقاش.

| البند | تقدير تخطيطي (دولار) |
|-------|----------------------|
| تصميم UX/UI ونظام التصميم | 8,000 – 25,000 |
| تطوير Flutter (MVP) | 25,000 – 80,000 |
| باك اند + CMS + AI endpoints | 10,000 – 35,000 |
| محتوى 300–500 وصفة (كتابة + تجريب + تصوير) | 15,000 – 60,000 (تقريبًا 30–120 دولارًا للوصفة المكتملة) |
| QA واختبار أجهزة | 3,000 – 10,000 |
| تسويق الإطلاق وASO | 5,000 – 30,000 |
| بنية سحابية/AI شهريًا (بداية) | 200 – 2,000 / شهر |
| قانوني (سياسة الخصوصية، العلامة، العقود) | 1,500 – 6,000 |
| حسابات المتاجر | ~125 (Apple سنويًا 99 + Google مرة واحدة 25؛ تحقق من الأسعار الحالية) |
| **إجمالي MVP (نطاق عريض)** | **≈ 70,000 – 250,000** |

**طرق تخفيض التكلفة:** الانطلاق بسوق واحد ولهجة واحدة، 200–300 وصفة نخبوية، تأجيل الكاميرا/AI إلى V1، استخدام CMS جاهز.

## 4. قرارات «ابدأ / لا تبدأ» (Go/No-Go) في نهاية الاكتشاف

| المعيار | العتبة |
|---------|--------|
| نسبة المهتمين بالتجربة الفعلية في اختبار Wizard of Oz | ≥ 40% يعودون لاستخدامها مرة ثانية خلال أسبوعين |
| وضوح الاستعداد للدفع (استبيان + اختبار Paywall وهمي) | ≥ 3% نية دفع عالية |
| جدوى المحتوى: كلفة وصفة مكتملة | ≤ الهدف المخطط |
| وضوح التمايز عن SuperCook/سيدتي وغيرها | يُلاحظ من المستخدمين في الاختبار |

## 5. مؤشرات تتبع المشروع (OKRs مقترحة للإصدار الأول)

- **O1: أفضل تجربة إدخال مكونات.**
  - KR: متوسط زمن «أول نتيجة» ≤ 45 ثانية.
  - KR: نسبة من يضيفون ≥ 3 مكونات ≥ 70%.
- **O2: محتوى موثوق.**
  - KR: متوسط تقييم الوصفات ≥ 4.5.
  - KR: نسبة «نجحت الوصفة» ≥ 90%.
- **O3: عادة يومية.**
  - KR: الاحتفاظ D7 ≥ 30%، D30 ≥ 15–20% (طموح).
- **O4: جدوى مالية.**
  - KR: تحويل إلى Pro ≥ 3%.
  - KR: تكلفة AI/مستخدم نشط ضمن الحد المخطط.
